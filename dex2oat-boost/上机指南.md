# 上机指南（dex2oat-boost）

> 仅 Magisk 模块方案。原 LSPosed 方案（方案 A）已于 2026-11-04 移除。
> 原理与产物路径见 [`README.md`](README.md)（本指南不重复）。
> 模块的配置项 / 设计取舍见 [`magisk模块/README.md`](magisk模块/README.md)（本指南不重复）。
> 本方案**未在目标设备完整真机验证**——各节末尾的〈未验证项〉逐条列明。

## 统一前置

- 设备**已 root**（KernelSU 或 Magisk 其一）。
- **系统与 ROM**：带 `pm.dexopt.*` 属性的 Android ROM；目标 ROM 为 Android 16（SDK 36）。
- 一个 **su 终端**（Termux / MT 管理器终端 / `adb shell` + `su` 均可）。
- 一个**测试 APK**（任意小 APK）。
- 通用复核命令（看装后档位）：
  ```
  dumpsys package <被测包名> | grep -i dexopt
  ```
  期望出现该包处于 `speed` 相关（不同 ROM 字段名略异，找 `filter=speed` / `[status=speed]` 之类）。

## Magisk 模块（纯 root）

产物：`magisk模块/产物/dex2oat-boost-magisk.zip`（md5 `a70c1adb1a8beae142ed780ee19abf1e`）。

### M-1　刷入 zip

**Magisk / KernelSU 管理器 → 模块 → 从本地安装**，选 `dex2oat-boost-magisk.zip`。
- **期望**：刷入无报错，模块列表出现 `dex2oat-boost`。
- **不符**：报错 → 确认 zip 完整（md5 见上），换管理器版本重试。

### M-2　重启设备

- **期望**：重启后属性设置与守护进程一起生效。
- **不符**：不重启 → 属性未写、守护未跑（见 M-3 / M-4）。

### M-3　核对降档属性

```bash
su -c 'getprop pm.dexopt.install'
su -c 'getprop pm.dexopt.install-fast'
```
- **期望**：均输出 `skip`。
- **不符**：
  - 仍是系统默认（通常 `speed-profile`）→ 看日志有无 `orig pm.dexopt.install=…` 行：有说明守护执行过降档，但写入被 `resetprop`/`setprop` 拒绝（SELinux，属待真机确认项，本期无解）；
  - 连 `orig` 行都没有 → 守护没起来 → 看 M-4。

### M-4　核对守护进程

```bash
su -c 'ps -A | grep dex2oat-boost-daemon'
```
- **期望**：有一个 `dex2oat-boost-daemon.sh` 进程。
- **不符**：没有 → 看门狗没起来 → 先确认 `su -c 'getprop sys.boot_completed'` 为 `1`，再看：
  ```bash
  su -c 'grep service.sh： /cache/dex2oat-boost.log | tail -n 20'
  ```
  应含「开机完成，启动守护进程」；若含「守护进程退出（rc=…），5 秒后重启」则守护反复崩，查主日志其余行（M-6）。

### M-5　装一个测试包

经任意方式装上测试 APK（`adb install -r <测试.apk>` 或手机点装），等 **15~30 秒**（轮询 + 3 周期倒计时 + 编译）。
- **期望**：M-6 日志出现该包。
- **注意**：守护**首次运行只建立基线、不编译任何既有应用**；只有「基线之后新出现 / 变更」的包才会编译。**必须在模块跑起来之后再装**测试包。

### M-6　看守护日志

```bash
su -c 'tail -n 50 /cache/dex2oat-boost.log'
```
- **期望**出现两行（行首时间为 `日 时:分:秒`）：
  ```
  17 12:00:20 com.example.app dex2oat   ← 开始编译
  17 12:00:31 com.example.app speed     ← 编译结束（时间是结束时刻）
  ```
- **不符**：
  - 只有 `dex2oat` 行、没有 `speed` 行 → 还在编译，或在等 `pm path` 指向新目录（就绪门禁，属正常等待，最多 10 分钟）；过一会再看。
  - 出现 `<包名> speed fail` → 重试 `COMPILE_RETRY_MAX` 次仍失败，看该包能否手动 `cmd package compile -m speed <包名>`。
  - 完全没有该包 → 确认是「模块生效之后才装的」（首轮只建基线）；再确认包目录已在 `/data/app`（`su -c 'ls /data/app'`）。

### M-7　复核装后档位

```bash
su -c 'dumpsys package <被测包名> | grep -i dexopt'
# 或
su -c 'cmd package dump <被测包名> | grep -i filter'
```
- **期望**：该包处于 `speed` 相关。
- **不符**：仍 `verify` / `speed-profile` → 没被重编译 → 回 M-6。

### M-8　卸载与属性还原

管理器里卸载模块，或运行 `uninstall.sh`。卸载会：停守护与看门狗、把降档属性还原为**本次开机记录的原值**（取自 `/cache/dex2oat-boost.log` 的 `orig` 行，仅当前这次开机有效）、删 `/cache/dex2oat-boost.log`。
> `pm.dexopt.*` 是**运行期属性**，**重启即回归系统默认**；不重启时卸载也会尝试还原。停用（不卸载）后重启即恢复原状。

### 已知未在真机验证的项

（来源：实施报告 §八 / §10.5，如实声明。）

1. **未做真机验证**，以下均需真机复核：
   - `resetprop -n` / `setprop` 对 `pm.dexopt.*` 的写入是否被 SELinux 放行；
   - 本机 KernelSU 的 `/data/adb/ksu/bin/resetprop` 是否存在可用；
   - `/data/app` 目录名形态（`~~<base64>==/<包名>-<hash>`）与「第一个 `-` 前为包名」是否成立；
   - `cmd package compile -m speed <包名>` 输出文本是否含 `Success`；
   - 并发编译是否真并行（PMS / installd 可能串行排队）；
   - 覆盖安装时 `pm path` 是否如期先指旧目录、后指新目录（就绪门禁依赖此行为）。
2. **未做真刷入**：纯 shell 模块无编译产物，zip 未在真机 Magisk/KSU 上实际刷过。
3. 依赖 KernelSU/Magisk 的 `service.sh` 开机执行机制；换 root 方案或 OTA 后可能需重新部署。
4. 本目标 ROM `pm.dexopt.install` 的默认值未知。

### 出问题先看哪里

1. `su -c 'cat /cache/dex2oat-boost.log'` —— 唯一日志：`orig` 原值、设置 skip 的结果、每包的 `dex2oat` / `speed`、看门狗行（带 `service.sh：` 前缀，可看守护是否起来 / 反复重启）。
2. `su -c 'grep orig /cache/dex2oat-boost.log'` —— 本次开机记录的原属性值。
3. `su -c 'cat /data/adb/modules/dex2oat-boost/bin/state.tsv'` —— 基线快照（判断某包是否被判为「新增」）。
4. 配置调整见 [`magisk模块/README.md`](magisk模块/README.md) §五（`config.prop`，改完**重启生效**）。

## 常见坑

- **先刷模块，再装测试包**——否则基线窗口错过。
- 守护首次运行只建立基线、不编译既有应用；既有应用需要时手动 `cmd package compile -m speed <包名>`。
