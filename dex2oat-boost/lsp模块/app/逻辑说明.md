# 钩子逻辑说明

编译/部署步骤见 [`../README.md`](../README.md)；验收证据见实施方案存放区的《安装器dex2oat-hook-实施报告.md》。

## 0. 全局约束

- **作用域**：`xposedscope` = `com.miui.packageinstaller`。`MainHook.handleLoadPackage` 首行即
  `PkgNames.matchesTarget(packageName)`，非目标进程**直接 return，不注册任何 hook**。
- **部署前提（root 授权对象）**：只需在 KernelSU/Magisk 给**安装器** `com.miui.packageinstaller` 授权 root；**模块自身 APK `com.mengdao.dex2oatboost` 不需要、也无法从 root 授权获益**——它无任何自有组件/进程，代码只被注入安装器进程执行，`su` 请求的发起方永远是安装器。判定方法见 [`../README.md`](../README.md) §三。
- **零 root 优先**：主路径（②）不依赖 root；root 仅作 ② 失败后的降级通道（③）。
- **固定档位**：常量 `MainHook.INSTALL_FILTER="verify"`、`DexoptTrigger.TARGET_FILTER="speed"`，各只有一处。
- **异常不外逃**：每个 hook 回调内部各套 try-catch；降级链（IpmBridge→RootShell）同样是 try-catch。
- **重编译时机**：安装完成立即、后台异步（单线程池，不阻塞安装器 UI）。
- **可观测性**：`Mlog` 双通道输出（`android.util.Log` tag `Dex2OatBoost` + `XposedBridge.log` 落进 LSPosed 的 `LSPosedFramework` 流）；`handleLoadPackage` **最前面**无条件记一行 `handleLoadPackage pkg=… process=… sdk=…`，用于确认「模块是否被注入本进程」。

## 1. 类职责

| 类 | 职责 | 依赖 |
|---|---|---|
| `MainHook` | LSPosed 入口；注册 hook（① `createSession` + 完成广播注册） | xposed |
| `core.PkgNames` | 作用域匹配 + 包名合法性（su 参数白名单） | 纯 Java |
| `core.HookedCall` | 反射调 `setDexoptCompilerFilter`，失败折叠为 false | 纯 Java |
| `core.DexoptArgBuilder` | 按运行期签名构造 `performDexOptMode` 实参 | 纯 Java |
| `core.SessionRegistry` | `sessionId→pkg` 表（有界 FIFO） | 纯 Java |
| `HiddenApi` | 尽力而为的 hidden-API 豁免（LSPosed 自带库） | android |
| `IpmBridge` | ② 取 `IPackageManager` 并调 `performDexOptMode` | android |
| `RootShell` | ③ `su -c "cmd package compile …"` | android |
| `DexoptTrigger` | ②③ 调度（单线程串行） | android |
| `InstallCompleteReceiver` | 安装完成广播 + 归属判定/完成入口 | android |
| `Mlog` | 日志出口（双通道） | android |

## 2. ① 安装期降档

- **锚点**：`android.content.pm.PackageInstaller#createSession(PackageInstaller$SessionParams)`
  —— 系统框架类、免混淆；MIUI 主链路（`p102o2.e.H`）与 AOSP 兼容支路（`InstallStaging.k`）**都经此**。
- **before**：`param.args[0]` 即 `SessionParams`；
  - 读 `appPackageName` 字段（可能为 null，读不到不阻断）；
  - `HookedCall.trySetDexoptCompilerFilter(sp, "verify")` 反射置档；
  - 结果与包名经 `param.setObjectExtra("pkg", pkg)` 传给 after。
- **after**：`param.getResult()` 即 `sessionId(int)`；`SessionRegistry.record(sessionId, pkg)`。
- **降级**：设备 <Android 15 时 `setDexoptCompilerFilter` 不存在 → `NoSuchMethodException` → 折叠为 false，
  **只记日志、不降档，安装照常**；② 不受影响照常执行。

## 3. ② 装后重编译（零 root 主路径）

- **完成信号（安装完成广播，幂等去重）**：
  1. **广播**：进程启动时（hook `android.app.Instrumentation#callApplicationOnCreate`）动态注册
     `ACTION_PACKAGE_ADDED / ACTION_PACKAGE_REPLACED`（框架级，两条支路通吃，不依赖 MIUI 混淆类名）。
     - 覆盖安装时 PACKAGE_ADDED(REPLACING=true) 与 PACKAGE_REPLACED 都会到，只处理后者，避免重复触发。
     - API 33+ 用 `RECEIVER_NOT_EXPORTED` 注册，外部无法伪造。
  - 经 `InstallCompleteReceiver.handleCompletion` → `DexoptTrigger.triggerOnce`（120s 窗口幂等去重）。
  - **局限（如实）**：广播为**动态注册 / 进程内**，**不抵御安装器进程被杀**（那需清单级接收器，本模块刻意不做）。
  - **必须动态注册（不可改用清单接收器）**：`PACKAGE_ADDED`/`PACKAGE_REPLACED` 是 **protected-broadcast**，且**不在**隐式广播豁免名单；系统发的通用广播 `flags=0`（不带 `FLAG_RECEIVER_INCLUDE_BACKGROUND`），只有「定向发给 installer 包」的那一次才带该 flag。后果：**清单（manifest）注册的接收器在应用处于后台/缓存态时收不到**（`BroadcastSkipPolicy.disallowBackgroundStart`）。而**动态注册**的接收器即便标 `RECEIVER_NOT_EXPORTED`，由 system_server（uid 1000）发出的广播仍会送达（`ActivityManager.canAccessUnexportedComponents` 对 ROOT/SYSTEM uid 直接放行）。故本模块的完成信号**为动态注册 / 进程内，无任何清单接收器**——这是必需，不是偏好。
  - **已移除的 commit 兜底（如实）**：旧版曾将 hook `PackageInstaller$Session#commit(IntentSender)` 读会话 id 作为第二路信号。**Android 16 的 `PackageInstaller.Session` 只剩一个 `IPackageInstallerSession` binder 字段，已无任何 int 会话 id 字段**（AOSP 官方 r tag `android-16.0.0_r1` 已核），该路径在 A16 上取不到值、恒为空转，故**整体移除**（真机亦报 `commit 兜底：无法解析会话 id，跳过`）；广播这一路真机已验证可用。
- **归属判定**：命中 `SessionRegistry`（① 登记过）**或** `getInstallSourceInfo(pkg).getInstallingPackageName()`
  就是本安装器，才处理；否则忽略。
- **调用**：`IpmBridge.performDexOptMode(pkg, /*checkProfiles*/false, "speed", /*force*/true, /*bootComplete*/true)`
  - binder 取法：`ServiceManager.getService("package")` → `IPackageManager$Stub.asInterface(...)`。
  - 实参顺序由 `DexoptArgBuilder` 依**运行期方法签名**决定：
    - 签名 A（Android 15/16；原文与出处见 `../../../../.claude/subagent方案存放区/安装器dex2oat-hook-ART源码核实.md` 的〈七、AOSP 官方 r tag 复核〉节）：
      `(String pkg, boolean checkProfiles, String filter, boolean force, boolean bootComplete, String splitName)`
      → `{pkg, false, "speed", true, true, null}`
    - 签名 B（旧版多 `instructionSet`）：`(String, String, boolean, String, boolean)` → `{pkg, null, false, "speed", true}`
    - 无法识别的签名返回 null → 直接走 ③。真机若出现「签名未识别」日志，按实测签名补一条分支。

## 4. ③ 自动降级（root 通道）

- 触发条件：② 抛 `SecurityException`、返回 false、或任何异常。真机实测该 `SecurityException` **不是**「安装者例外」那条（它已放行，`callingUid=installerUid`），而是其后的**应用休眠门禁**（`AppHibernationService` 强制 `MANAGE_APP_HIBERNATION`，该权限保护级 `signature|installer`、安装器拿不到）——即非 root 的 ② 在 A16 上**结构性不成立**，详见方案存放区 `dex2oat-boost-performDexOptMode权限链核实.md`。
- 动作：`RootShell.compile(pkg, "speed")` → `ProcessBuilder("su","-c","cmd package compile -m speed -f <pkg>")`。
  - 包名先经 `PkgNames.isValidPackageName` 白名单校验（防命令注入）；
  - 读输出放后台线程，`waitFor(90s)` 超时可控；
  - 退出码 0 视为成功。
- 再失败：仅记日志，交给系统 bg-dexopt 兜底（不改任何状态）。

## 5. 隐藏 API 获取方式

- `PackageInstaller.SessionParams.setDexoptCompilerFilter`（Android 15 引入，`@hide`）→ 直接反射调用。
- `IPackageManager.performDexOptMode`（`@hide`，注释「exposed only for the shell command」）→ 反射 + binder。
- `ServiceManager` / `IPackageManager$Stub` 均为隐藏类 → 反射 `Class.forName`。
- LSPosed 注入进程通常已放行 hidden API；`HiddenApi.tryExempt()` 额外尝试 LSPosed 自带的
  `org.lsposed.hiddenapibypass.HiddenApiBypass.addHiddenApiExemptions("L")` 兜底；不可用只记日志，不改行为。

## 6. 未验证项（真机）

1. 目标 ROM（HyperOS 2 底包 / HyperOS 3）上「安装者例外」是否成立、`setDexoptCompilerFilter` 是否生效；
2. `ACTION_PACKAGE_ADDED/REPLACED` 在安装器进程内的实际送达时机；
3. MIUI 安装器实际走主链路还是 AOSP 兼容支路（主锚点两支通吃，风险可控）；
4. `IPackageManager.performDexOptMode` 在目标 ROM 的确切签名是否命中签名 A。
   —— 签名 A 已在 **AOSP 官方 r tag** 核实（形参逐位一致；`setDexoptCompilerFilter` 同分支仍在、同名同签名）。
   证据见 `../../../../.claude/subagent方案存放区/安装器dex2oat-hook-ART源码核实.md` 的〈七、AOSP 官方 r tag 复核〉节。
   目标 ROM 是否原样保留、以及实测签名仍须真机确认——未核实前，② 一旦签名/权限不成立会**静默**落 ③。

> **完成信号说明**：完成信号为**动态注册 / 进程内**的安装完成广播，不抵御安装器进程被杀；经 `triggerOnce` 幂等去重。
