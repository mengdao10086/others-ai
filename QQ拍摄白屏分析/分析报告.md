# QQ 拍摄白屏分析报告

分析对象：QQ 9.1.67（`base (4).apk`）+ Adreno GPU 驱动模块 `GPU_v@837.0.6M-KSU.zip`
设备：Redmi K60（`XIAOMI_23013RK75C`，SM8475 / Adreno 730），ROM `K60_移植17 3.0.318[68F32]`
日期：2026-11-11
真机日志：`D:\下载\LocalSend\QQ拍摄logcat原始.log`（15.0 MB / 74,364 行，相关会话 20:04:44–20:04:57）

## 实测验证记录（2026-11-11，用户真机）

1. **MT 管理器终端的 `su -c '<命令>'` 不可用**：单引号、双引号都会把整条
   `rm -rf <路径>` 当成一个文件名，报
   `bash: line 1: rm -rf /data/...: No such file or directory`。
   这是 MT 终端对 `-c` 参数的引号处理问题，不是路径不存在。
   **正确写法：先 `su` 进入 root shell，再另起一行直接执行命令**：
   ```
   su
   rm -rf /data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64
   exit
   ```
2. **用户按上述方式删除整个 `BASIC_64` 后，QQ 拍摄恢复正常**。
   说明：
   - shader 缺失确实是白屏的直接原因；
   - QQ 在资源包被**整体删除**后会重新下载/解压并补全，不是永不补；
   - `isAEKitNeedDownload=false` 只代表**当前这一轮/当前进程**不补，
     不代表整包缺失后也不补。日志里只删了 `shaders/` 子目录（资源包其余文件完好），
     QQ 的自检认为包是完整的，所以当场没补；整包删掉后才会触发重下。
3. **“卸载模块恢复”的解释（推断）**：`uninstall.sh` 确实也含同一行
   `find /data/data/* -iname "*shader*"`（原文与行号见第三节），但卸载执行时
   QQ 的 `shaders/` 目录早已被安装脚本删掉，find 对 QQ 已无可删。
   恢复更可能来自卸载/重启后 QQ 重新检查并补全资源包（与删 `BASIC_64` 后恢复同一路径）；
   也不能排除“重启改变了 QQ 的资源检查状态”。具体触发点未逐秒验证。
   如果先修好资源再卸载模块，`uninstall.sh` 会再删一次——所以顺序很重要。
   **驱动 837 是否有独立影响，仍需第七节 D 的对照实验判定。**

## 结论

**白屏的直接原因不是 GPU 驱动二进制，而是驱动模块的“清缓存”脚本把 QQ 的 AEKit 动态资源包里的 `assets/shaders/` 目录整个删掉了。**

模块的安装脚本 `customize.sh` 与卸载脚本 `uninstall.sh` 中都有这一条：

```sh
find /data/data/* -iname "*shader*" -exec rm -rf {} +
```

QQ 光影相机的着色器放在：

```
/data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64/<hash>/assets/shaders/essl/
```

目录名 `shaders` 命中 `*shader*`，被 `rm -rf` 递归删除。真机日志直接显示这些文件不存在：

```
loadMem open file failed! file path = .../assets/shaders/essl/vs_simple.bin
  message = FileReader: Failed to open file.
loadProgram but vertex shader is invalid! shader name = vs_simple
LightEngine ... ReadSample error!
```

同一资源包里的 `assets/material/video_empty/template.json` 能正常加载，说明**只删了 `shaders` 目录**，不是整包下载失败。QQ 的资源自检虽然报 `checkBundleResources fails`，但随后 `isAEKitNeedDownload=false`、`bundle all done`，**本轮没有补下载**（只少子目录时它认为包是完整的），所以缺失持续存在，拍摄页无法正常出图（白屏）。**整包删掉后 QQ 会重下并恢复（用户实测）。**

根因排序（第 1、2 条已被用户实测闭环确认）：

1. **模块的安装/卸载清理脚本误删 QQ 的 AEKit shader 资源**（直接原因，证据强度：高）。
   命令：`find /data/data/* -iname "*shader*" -exec rm -rf {} +`（`customize.sh` 与
   `uninstall.sh` 均有）；命中路径：
   `.../app_lib/qq_bundle_new/BASIC_64/<hash>/assets/shaders/`。
2. **QQ 只对“整包缺失”触发重下，对“只少 shaders 子目录”当场不补**（白屏持续的原因，证据强度：高）。
   日志：`checkBundleResources fails` 之后 `isAEKitNeedDownload=false`、`bundle all done`，
   缺失一直保留到拍照时；用户实测：**删掉整个 `BASIC_64` → QQ 重下/重解压 → 拍摄恢复**。
3. **GPU 驱动 v837 是否有独立影响**（证据强度：低/未证实，待对照实验）。
   日志无 `EGL_BAD_*` / `GL_INVALID_*` / linker / `dequeueBuffer` 错误；
   `EglImage dataspace changed` 只是非致命提示。要定死需“重装模块但删掉 find 行”的对照实验（见第七节 D）。

证据强度：**高**。
- 日志直证：着色器文件不存在、程序创建失败、`ReadSample error`。
- 脚本直证：安装/卸载脚本的删除命令与 QQ 的 `shaders` 目录精确匹配。
- **用户实测闭环**：删除整个 `BASIC_64` → QQ 重下/重解压 → 拍摄恢复；“卸载模块恢复”推断由同一重下机制解释（待对照实验进一步确认驱动是否也有独立影响）。
- 现象吻合：系统相机与其他 App 不依赖 QQ 的 AEKit 资源包，所以不受影响。
- 驱动侧：全程没有 `EGL_BAD_*` / `GL_INVALID_*` / shader 链接失败 / linker 失败；`GPUInfo` 显示 `Adreno (TM) 730 ... OpenGL ES 3.2 V@0837.0.6`，驱动本身已正常生效。

## 三、驱动包改了什么（一层）

**改动层级：vendor 用户态图形栈整体替换 + 安装脚本清理，不动 camera HAL、gralloc HAL、内核、HWC、SurfaceFlinger。**

替换/新增：

| 类别 | 文件 |
|------|------|
| EGL/GLES | `/vendor/lib64/egl/libEGL_adreno.so`、`libGLESv1_CM_adreno.so`、`libGLESv2_adreno.so`、`eglSubDriverAndroid.so`、`libq3dtools_*` |
| Vulkan | `/vendor/lib64/hw/vulkan.adreno.so` |
| 系统层/编译器 | `libgsl.so`、`libllvm-glnext.so`、`libllvm-qgl.so`、`libllvm-qcom.so`、`libadreno_utils.so`、`libadreno_compiler_cl.so` |
| OpenCL/其它 | `libCB.so`、`libOpenCL*.so`、`libkcl.so`、`libkernelmanager.so`、`gpu++.so` 等 |
| 显示/缓冲映射 | `vendor.qti.hardware.display.mapper@2.0/3.0/4.0.so`、`mapperextensions@1.0~1.3.so`、`libdmabufheap.so` |
| 固件 | `/vendor/firmware/a630/a650/a660/a730/gen71100_sqe.fw`（K60 对应 `a730_sqe.fw`） |
| 特性声明 | `/vendor/etc/permissions/*.xml` |
| 运行期配置 | `qgl_config.txt` → `/data/vendor/gpu/qgl_config.txt` |

版本：`0837.0.6`，Build Date `11/10/25`，GLSL 编译器 `E031.50.14.00`。
来源：K11MCH1/AdrenoToolsDrivers 发布页写明 “v837 extracted from Quest 3”，Quest 3 是 Adreno 740；本机是 Adreno 730，属于跨代移植（发布页标注 “For a7xx”）。

**安装/卸载脚本的危险动作**（`customize.sh`，解码后原文；`uninstall.sh` 里也有相同的 `find ... *shader* ... rm -rf` 行）：

```sh
find /data/user_de/*/*/*cache/* -iname "*shader*" -exec rm -rf {} +
find /data/data/* -iname "*shader*" -exec rm -rf {} +
find /data/data/* -iname "*graphitecache*" -exec rm -rf {} +
find /data/data/* -iname "*gpucache*" -exec rm -rf {} +
find /data_mirror/data*/*/*/*/* -iname "*shader*" -exec rm -rf {} +
...
rm -rf /data/dalvik-cache/*/*
rm -rf /data/cache/*
rm -rf /data/system/package_cache/*
rm -rf /data/resource-cache/*
```

第一条目标是 `*cache*` 目录，尚可接受；第二条 `find /data/data/* -iname "*shader*"` 是**递归全盘匹配任意路径名含 shader 的文件/目录**，会命中 App 的资源目录，而不只是缓存。QQ 的 AEKit `.../assets/shaders/` 正好命中。

`uninstall.sh` 逐行原文（无任何条件判断）：

```sh
1  find /data/user_de/*/*/*cache/* -iname "*shader*" -exec rm -rf {} +
2  find /data/data/* -iname "*shader*" -exec rm -rf {} +
3  find /data/data/* -iname "*graphitecache*" -exec rm -rf {} +
4  find /data/data/* -iname "*gpucache*" -exec rm -rf {} +
5  find /data_mirror/data*/*/*/*/* -iname "*shader*" -exec rm -rf {} +
6  find /data_mirror/data*/*/*/*/* -iname "*graphitecache*" -exec rm -rf {} +
7  find /data_mirror/data*/*/*/*/* -iname "*gpucache*" -exec rm -rf {} +
```

KernelSU 文档说明 `uninstall.sh` 在模块删除前以阻塞方式执行；即便某些管理器/版本不执行它，也不影响结论：卸载时 QQ 的 `shaders/` 目录已经不存在（安装时已删），`uninstall.sh` 的 find 要么无可删、要么根本没跑，两种情况都不会“恢复”文件。恢复只能来自卸载/重启后 QQ 重新检查并补全资源包（与用户删除 `BASIC_64` 后的恢复同一条路径）；具体触发点未逐秒验证。若先在 QQ 里修好资源、再卸载模块，`uninstall.sh` 会再删一次。

完整清单见 [证据/驱动包文件清单.txt](证据/驱动包文件清单.txt)，依赖关系见 [证据/驱动版本与依赖.txt](证据/驱动版本与依赖.txt)。

## 四、QQ 的相机路径

QQ “拍摄”走腾讯 **AE / 光影相机 SDK**（`com.tencent.aelight.camera`），不是简单调系统相机：

```
Camera2（qqcamerakit，Camera2 优先；不支持时回退 Camera1）
   ↓  setPreviewTexture / addTarget(Surface)
SurfaceTexture（绑定 GL 纹理名）
   ↓  EGLImage 导入（gralloc buffer → GL）
GL_TEXTURE_EXTERNAL_OES / samplerExternalOES
   ↓  AEKit / Light SDK 滤镜链（FBO、美颜、贴纸、LUT）
GLSurfaceView 上屏
```

关键点：

- `AECameraGLSurfaceView extends android.opengl.GLSurfaceView`；`setEGLContextClientVersion(2)`，自定义 `EGLContextFactory` 先请求 ES3、失败退 ES2；`setEGLConfigChooser(8,8,8,8,0,0)`；`setRenderMode(0)`（`RENDERMODE_WHEN_DIRTY`）。
- 相机纹理：`GLES20.glGenTextures()` + `new SurfaceTexture(textureId)`。
- 滤镜着色器：`#extension GL_OES_EGL_image_external : require`、`uniform samplerExternalOES`、`glDrawArrays(GL_TRIANGLE_FAN, 0, 4)`，输出到 FBO 再上屏。
- `AECameraManager extends com.tencent.qqcamerakit.capture.b`；`realStartPreview()` 把 `SurfaceTexture` 交给 `cameraProxy.r(...)`。
- Camera2 实现 `com.tencent.qqcamerakit.capture.camera2.b`：`new Surface(surfaceTexture)` + `createCaptureSession([...])`；Camera1 兜底同样 `setPreviewTexture`。
- **GPU 白/黑名单机制存在但在本机不生效**：`com.tencent.aelight.camera.ae.util.j` 按 `GL_RENDERER` 解析 Adreno/Mali 型号，但 GPU 信息只在 SDK < 24 时通过 OpenCL 探测；本机 SDK ≥ 34，`this.a` 保持空，`w()` 不匹配任何规则。按机型黑名单（`assets/short_video_device_rule_config.xml`）仍生效，K60 不在名单里。
- **没有 GL 扩展能力探测/回退**：未发现 `glGetString(GL_EXTENSIONS)` 判断；`GL_OES_EGL_image_external` 是硬依赖，shader 里 `require`，失败即报错。

所以：QQ 的预览必须经过 **AEKit 的 shader 资源 + GL 外部纹理 + FBO 滤镜**，其中 shader 资源来自 `/data/data/.../assets/shaders/`，正是被模块脚本删掉的那一块。

## 五、为什么系统相机 / 其他 App 不受影响

| | 系统相机 | 其他多数 App | QQ 拍摄 |
|---|---|---|---|
| 预览实现 | Camera HAL → SurfaceView / HWC 直出 | 多数调系统相机 intent 或用 SurfaceView 预览 | Camera2 → SurfaceTexture → **AEKit shader 滤镜链** → GL |
| 是否依赖 `/data/data/.../shaders` | 否 | 否（shader 多在 APK 内或不用） | **是**，AEKit 动态资源包 |
| 本次模块删除 `*shader*` 的影响 | 无 | 无（路径不匹配） | **命中并删除** |

不是 Camera1/Camera2 的差异（QQ 走 Camera2，日志里 `Camera2 openCamera2/onConfigured` 正常），也不是 GPU 白名单分支（本机 SDK ≥ 34 不生效）。决定性的差异是 **QQ 多了一层从 `/data/data` 加载的 AEKit 着色器资源**，而模块的清缓存命令把这一层删了。

## 七、处置方案

### A. 修 QQ 的 shader 资源（已实测有效，推荐）

**MT 终端注意**：`su -c '<命令>'` 在 MT 管理器终端里会被错误处理（单引号、双引号都一样），
报 `bash: line 1: rm -rf /data/...: No such file or directory`——这是引号/参数传递问题，
不是路径不存在。**请先 `su` 进 root shell，再另起一行执行命令**。

1. 先只读确认路径（不要直接删）：
   ```
   su
   ls -ld /data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64
   ls -l /data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64/*/assets/shaders/essl | head
   exit
   ```
   - 能看到 hash 目录，说明路径存在（之前 `su -c` 的报错是引号问题）。
   - 如果 `essl` 不存在/为空，确认 shader 被删。

2. 删除整个 `BASIC_64`（只删 QQ 已下载的 AE 资源包，不删聊天记录；QQ 会重新下载）：
   ```
   su
   rm -rf /data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64
   exit
   ```
   **用户已实测：删除后 QQ 拍摄恢复正常。**

3. 打开 QQ → 拍摄页，保持联网，等待 QQ 重新下载/解压资源包。

4. 验证：
   ```
   su
   ls -l /data/user/0/com.tencent.mobileqq/app_lib/qq_bundle_new/BASIC_64/*/assets/shaders/essl | head
   exit
   ```
   应能看到 `vs_simple.bin`、`vs_epm.bin`、`vs_boxblur.bin`、`fs_adjustments.bin` 等；
   再开拍摄页，logcat 不再有 `vertex shader is invalid`。

5. 备选：清除 QQ 数据/重装也能恢复，但会丢本地登录状态；单纯“清除缓存”通常不够，
   因为 `app_lib` 不在 `cache` 下。

### B. 修模块脚本，避免再次发生（重要）

把模块 zip 解压，编辑 `customize.sh` **和 `uninstall.sh`**（两份都有删除逻辑），把危险的两条改成只清缓存目录：

```sh
# 改前
find /data/data/* -iname "*shader*" -exec rm -rf {} +
find /data/data/* -iname "*gpucache*" -exec rm -rf {} +
find /data/data/* -iname "*graphitecache*" -exec rm -rf {} +

# 改后（只清 cache）
find /data/data/*/cache -iname "*shader*" -exec rm -rf {} +
find /data/data/*/cache -iname "*gpucache*" -exec rm -rf {} +
find /data/data/*/cache -iname "*graphitecache*" -exec rm -rf {} +
```

`/data_mirror/...` 的同类命令也按同样思路收窄；或直接删掉这几行。改完重新打包刷入。

### C. 回滚驱动（可选，注意顺序）

如果不想继续用这个跨代驱动：

1. **只想停用驱动（推荐）**：在 KernelSU/Magisk 里“停用”模块，**不要点删除**。
   停用不会执行 `uninstall.sh`，不会二次删除 QQ 的 shader；重启后即回原厂驱动。
   停用前后的资源修复顺序无所谓。
2. **一定要删除模块**：删除会执行 `uninstall.sh`，若此时 QQ 的 shader 已恢复，会被再删一次。
   所以要么**先删除、重启、再做 A**，要么先改掉 `uninstall.sh` 的 find 行再删除。
3. `/data/vendor/gpu/qgl_config.txt` 由 uninstall.sh 删除；停用不会删，可手动确认。
4. 验证 QQ 拍摄恢复正常、`GPUInfo` 回到原厂版本。
5. **“卸载模块恢复”的解释（推断）**：卸载时 `uninstall.sh` 会跑同一行 find，但 QQ 的 `shaders/`
   早已被安装脚本删掉，find 对 QQ 已无可删；恢复更可能来自卸载/重启后 QQ 重新检查并补全资源包
   （具体触发点未逐秒验证）。如果先修好资源再卸载，`uninstall.sh` 会再删一次——所以顺序很重要。

### D. 对照实验：判断驱动 v837 是否有独立影响（可选）

目的：把“脚本删 shader”和“驱动二进制”两个因素分开。

1. 确认当前状态：QQ 拍摄正常（A 已修复）。
2. 解压模块 zip，编辑 `customize.sh` **和 `uninstall.sh`**，删除或注释掉这三类行：
   ```sh
   find /data/data/* -iname "*shader*" ...
   find /data/data/* -iname "*gpucache*" ...
   find /data/data/* -iname "*graphitecache*" ...
   ```
   重新打包，按原方式刷入。
3. 重启，打开 QQ 拍摄，**等待 10–15 秒不要退出**。
4. 判定：
   - 拍摄正常 → 白屏由脚本删除 shader 引起，驱动 837 没有独立影响。
   - 仍然白屏 → 驱动 837 对 QQ 有独立影响；此时再考虑回滚驱动或对 QQ 做模块排除（DenyList/按应用卸载）。
5. 无论结果，用 [脚本/QQ拍摄logcat测试.sh](脚本/QQ拍摄logcat测试.sh) 留一份日志（已加 AEKit/shader 过滤）。

### E. 等更新 / 反馈

- 向 Adreno Laboratory / 模块作者反馈：`customize.sh` / `uninstall.sh` 的 `find /data/data/* -iname "*shader*"` 会删 App 的 shader 资源，建议改为只清 cache。
- 关注后续模块版本是否修正这一行；QQ 版本更新本身不会恢复被删的本地资源（除非重下资源包）。

## 八、验证判据

| 现象 | 结论 |
|------|------|
| `loadMem open file failed .../assets/shaders/essl/*.bin` + `vertex shader is invalid` | **本次白屏根因**：AEKit shader 资源缺失 |
| 同 bundle 的 `material/*.json` 能加载，只有 `shaders/` 缺失 | 目录被选择性删除（与模块 `find *shader*` 吻合） |
| `isAEKitNeedDownload=false` / `bundle all done` 但文件仍缺 | 只少 `shaders/` 子目录时当场不补；**整包删除**后会重下（用户实测删 `BASIC_64` → 恢复） |
| `EGL_BAD_*` / `GL_INVALID_*` / `dequeueBuffer` 失败 / linker 失败 | 若有，才考虑 GPU 驱动或 buffer 导入问题；本次均为 0 |
| `EglImage dataspace changed, need recreate` | 非致命；本次仅预览启动 burst，之后停止 |
| `Camera2 onConfigureFailed` / `onError` | 相机会话/buffer 分配问题；本次无 |
| 恢复 shader 后仍白屏 | 再抓 logcat，重点看 EGL/GL 与 Camera2 回调 |
