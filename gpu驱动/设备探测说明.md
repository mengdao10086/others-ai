# 设备探测说明

脚本：[probe_gpu.sh](probe_gpu.sh) —— 全只读，不改任何文件 / 属性 / SELinux 策略。
结果同时打印到屏幕并写进**脚本同目录**的 `设备探测结果.log`。

## 怎么跑

**A. 电脑 + adb（推荐）**

```
adb push probe_gpu.sh /data/local/tmp/
adb shell su -c 'sh /data/local/tmp/probe_gpu.sh'
adb pull /data/local/tmp/设备探测结果.log
```

**B. 手机终端（MT 管理器 / Termux / 系统终端）**

把 `probe_gpu.sh` 复制到手机任意目录，`su` 之后执行 `sh probe_gpu.sh`，结果落在同目录的 `设备探测结果.log`。

脚本需要 root。如果不是 root，它会自己尝试 `su` 提权重跑一次；提权失败就只输出到屏幕、不写日志。

## 脚本查什么

| 段 | 内容 |
|---|---|
| A | 机型 / SoC / Vulkan HAL / ROM 版本 / SDK / 内核 |
| B | `graphicsengine` 二进制与 `graphicsengine.rc` 是否存在，rc 全文 |
| C | `/data/system/graphicsengine/pipelinecache/` 现有条目数与列表 |
| D | dmesg 里 graphicsengine / hwservicemanager_prop 的 avc 拒绝记录 |
| E | ★关键★ `(type graphicsengine)` 落在哪个策略组的 `.cil`；`hwservicemanager_prop` 的写法；同族先例 `miuibooster` 的权限集合 |
| F | `/dev/` 下 HIDL/AIDL 两条属性文件是否存在及其标签 |
| G | 有没有 `precompiled_sepolicy` |
| H | 抢占节点现值与标签、`init.qcom.post_boot.sh` 尾部 |
| I | magiskpolicy / KernelSU / 已装模块清单 |
| J | 可选：直接问 live 策略里有没有这些类型 |
| Z | 判据速览（脚本自己汇总的 5 条结论） |

## 我要从输出里读出的四件事

| # | 判据 | 决定什么 |
|---|---|---|
| 1 | B 段有没有 `graphicsengine.rc` | 这条补丁是否值得做 |
| 2 | E 段 `(type graphicsengine)` 落在哪个组 | 类型名带不带 `_32_0` 后缀 |
| 3 | D 段有没有 avc 拒绝 | 是"确实被拒"还是"另有原因" |
| 4 | H 段 preemption 现值 + post_boot 尾部 | 抢占补丁的落点与当前基线 |

跑完把 `设备探测结果.log` 整份贴回即可。
